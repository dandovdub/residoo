# Transcript-shaped secrets corpus

A fully synthetic, deterministic corpus of AI-agent session transcripts for
benchmarking secret scanners on data at rest, plus a machine-readable ground
truth (`truth.json`). It exists to answer one question honestly: given the
files an AI coding agent actually leaves on disk, what does each scanner
find, what does it miss, and what does it wrongly flag?

Everything here is reproducible from one seed. A hostile reader can rerun
`node generate.js`, get byte-identical output, and check every scoring claim
against `truth.json`.

## Layout

```
bench/corpus/
  generate.js          the generator (Node, zero dependencies, seeded PRNG)
  truth.json           ground truth manifest (all plants, exact values, file:line)
  data/home/           the fixture HOME that scanners are pointed at
    .claude/projects/<slug>/<uuid>.jsonl   72 session transcripts
    .claude/settings.json                  benign global config
    .claude/settings.local.json            config fixture with a planted token
    projects/acme-api/.mcp.json            project config fixture (--project mode)
    projects/acme-api/.claude/settings.local.json
```

`truth.json` deliberately lives OUTSIDE `data/home`. It contains every
planted value, so if it sat inside the scanned tree it would contaminate
every scanner's results. Harnesses must pin `HOME` (and `XDG_*`,
`USERPROFILE`, and agent-specific home variables) to `bench/corpus/data/home`
for every scanner invocation and must never scan the real home directory.

## Schema provenance

Record shapes (field names, nesting, enum-ish values, key order) were
extracted from real Claude Code transcripts, structure only, using a shape
extractor that never printed content. The corpus reproduces the observed
record kinds: user prompts (string content), assistant text / thinking /
tool_use records, tool_result records with the observed `toolUseResult`
variants (Bash `{stdout, stderr, interrupted, isImage, noOutputExpected}`,
Read `{type, file: {filePath, content, numLines, startLine, totalLines}}`,
Edit with `structuredPatch`, MCP object results), plus session meta records
(`mode`, `ai-title`, `custom-title`, `last-prompt`, `queue-operation`, and
the legacy `summary` record shape used by older versions). Tool output is
duplicated in `message.content` and `toolUseResult` on the same line, as in
real transcripts. No real content, path, or value was copied.

## Planted content classes

| Class | Count | What it tests | Scored |
| --- | --- | --- | --- |
| PLANT-PLAIN | 27 | pattern-true fakes in natural positions: user paste, file-read content in tool_result, command stdout, agent config files | headline recall |
| PLANT-JSON-NESTED | 6 | secrets inside JSON-stringified blobs inside tool_result content (double-encoded once serialized to JSONL) | headline recall |
| PLANT-ECHO | 4 | one distinct secret re-exposed across several tool_results in one session; tests distinct-vs-re-exposed counting | headline recall (distinct values) |
| PLANT-B64 | 5 | base64-wrapped secrets; a hard class, commonly missed by line-oriented scanners and defeated by decoding (gitleaks decodes in place) | separate, never folded into headline recall |
| PLANT-SPLIT | 3 | a secret split across two adjacent JSONL lines (an assistant turn streamed as two records sharing one message id); another labeled hard class | separate, never folded into headline recall |
| SUPPRESS-EXPECTED | 10 | placeholder-context values (X-runs, `<YOUR_TOKEN>` markers, `changeme`, the documented `AKIAIOSFODNN7EXAMPLE`) that a good tool suppresses or downweights | false positive if flagged as real |
| chaff | 45 tracked | realistic non-secrets: git SHAs, UUIDs, sha256 digests, base64 image fragments | precision reference |

Rule families covered by plants (12): AWS access key id, GitHub PAT, private
key block, JWT-shaped, connection string with password, Anthropic-shaped
key, Slack token, Stripe test-shaped key, Discord webhook, npm token, GitLab
PAT, generic bearer header.

## Why the fakes are safe to commit

Every planted secret is generated by the seeded PRNG with the correct
prefix, charset, and length for its family, and none was ever issued by any
provider. This is the CredData (Samsung) approach; AWS's documented example
key `AKIAIOSFODNN7EXAMPLE` is the canonical model and appears here only as a
SUPPRESS-EXPECTED fixture. Stripe values use the `sk_test_` shape only.
Because the values are fake and frozen by the seed, `truth.json` can list
them verbatim and harnesses can score by exact match instead of by fuzzy
location heuristics.

## Ground truth format

`truth.json` lists every plant with: stable `id`, `class`, `family`,
`vehicle` (where in the transcript it lives), `file` and 1-based `lines`,
`occurrences`, the exact `value`, and a `grep` anchor guaranteed to appear
literally and unescaped on the raw JSONL line (for multiline private keys
the anchor is one base64 body line; for PLANT-B64 it is the first encoded
line, with the full `encoded` form included; for PLANT-SPLIT both `parts`
are listed). Tracked chaff appears under `chaff` with the same addressing.

The generator verifies its own output before writing the manifest: every
anchor's actual line set must exactly equal the declared set corpus-wide (no
missing plants, no accidental duplicates or cross-contamination), split
values must not appear contiguously anywhere, raw values of base64 plants
must not appear anywhere, all planted values are unique, and every
transcript line must parse as JSON. A run that fails any check exits
non-zero and writes no manifest.

## Fairness notes

- No scanner-specific tuning. Plant positions, families, and encodings were
  chosen from how agent transcripts leak secrets in practice, not from any
  tool's rule list. The 12 families are NOT uniformly covered by every
  scanner, and the benchmark's own results show it: gitleaks and whatileaked
  ship no rules at all for three of them (connection strings with passwords,
  Discord webhooks, bearer Authorization headers), which accounts for their
  entire transcript-plain gap versus residoo. That decomposition is published
  in RESULTS.md, and a per-family recall table ships there and in
  scoreboard.json so any reader can recompute every class with any family
  subset. Why the contested families are in: connection strings and bearer
  headers in verbose curl or tool output are among the most transcript-typical
  leak shapes there are; the Discord webhook is the weakest inclusion and is
  named as such rather than defended. Counter-evidence that the mix was not
  tuned to residoo: residoo scores 0-for-4 on the stripe family across every
  class it appears in, agentsweep beats residoo on both plain and json-nested,
  and gitleaks ties residoo on the all-classes distinct-credentials line.
- Hard classes (PLANT-B64, PLANT-SPLIT) are labeled and scored
  separately precisely so that missing them does not silently drag down any
  tool's headline number, including tools that do catch them.
- SUPPRESS-EXPECTED cuts both ways: flagging placeholders as real secrets
  costs precision for any tool, including residoo.
- PLANT-ECHO defines recall over distinct values, so tools that report each
  re-exposure and tools that deduplicate are scored identically on recall;
  re-exposure counting is reported alongside, not blended in.
- The corpus is 100% synthetic. No real transcript content, file path, or
  value appears anywhere in it.

## Regenerating

```
node bench/corpus/generate.js            # rewrites data/ and truth.json in place
node bench/corpus/make-manifest.js       # rebuilds data/manifest.json for the scorer
node bench/corpus/generate.js /tmp/out   # or into another root
```

`make-manifest.js` derives the harness scoring manifest (`data/manifest.json`,
schemaVersion 1, one entry per exposure site) deterministically from
`truth.json`; run it after every regeneration. Its mapping decisions are
documented at the top of the script.

The seed is a constant in `generate.js` (`SEED = 20260902`). Two runs are
byte-identical; changing the seed produces a different but equally valid
corpus, which is the recommended way to check that a scanner is not
hardcoding this corpus's values.
