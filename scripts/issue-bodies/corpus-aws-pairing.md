Disclosed gap in bench/RESULTS.md: the corpus's AWS plants are bare AKIA-prefixed key IDs with no accompanying secret access key. Several tested tools (TruffleHog among them) have detectors that look for a paired secret key nearby and reasonably treat a bare key ID as an identifier rather than a credential, a defensible threat model that our current corpus doesn't test fairly.

The fix: for a defined subset of the AWS plant sites in `bench/corpus/generate.js`, add a plausible-looking (fake, pattern-true) paired secret access key near the existing AKIA plant, and update `bench/corpus/truth.json` so both the bare-id-only sites and the paired sites are scored and reported separately, never blended into one number. Read `bench/README.md`'s fairness rules and the existing AWS plant code before starting.
